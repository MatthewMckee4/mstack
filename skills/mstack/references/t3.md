# T3 Code adapter

This reference maps workflows to T3's live tools. It does not install T3 or supply model
access. Host instructions and live tool schemas take precedence over examples here.
Tool names may have a prefix such as `mcp__t3_code__`.

## Discover and route

Call `orchestrator_capabilities` before selecting a provider or model. Use the live
provider instance IDs, model IDs, option descriptors, and inherited options. Do not
substitute a native agent model list for the T3 catalog.

If the initial tool list omits T3, make one direct attempt to call its known capabilities
tool before declaring it unavailable. If tools are absent and `T3_ACP_MCP_NODE` is set,
the supported transport fallback is:

```sh
ELECTRON_RUN_AS_NODE=1 "$T3_ACP_MCP_NODE" ${T3_ACP_MCP_ENTRYPOINT:+"$T3_ACP_MCP_ENTRYPOINT"} acp-mcp-call orchestrator_capabilities '{}'
```

Use native agents for supported same-provider, same-model work only when no requested
or inherited model options need preserving. Use `delegate_task` for cross-provider work,
explicit T3 child tasks, unsupported native selections, requested model options, or
same-model inheritance with nonempty `inheritedOptions`. Put options in `target.options`,
not only the prompt. Do not reduce a requested reasoning level or ignore unsupported
options. Explain the mismatch. Verify returned provider, model, and options.

For example, using real values from the catalog:

```json
{
  "task": "A bounded brief with scope, checkout, acceptance checks, and expected evidence",
  "target": { "providerInstanceId": "FROM_CATALOG", "model": "FROM_CATALOG", "options": {} },
  "mode": "async",
  "clientRequestId": "unique-per-logical-task-stable-on-retry",
  "isolation": "worktree"
}
```

An explicit empty options object clears inherited options. Omit it when inheritance is
intended; use actual descriptor-supported settings when options are requested. Do not
copy the example unchanged or invent provider IDs.

## Own the child lifecycle

Use `isolation: "worktree"` for a child that needs a separate checkout. It starts at the
parent's local commit and runs project setup; uncommitted edits are not copied. Ensure
the necessary changes are committed within the user's authorization or supply an
explicit reviewed patch/snapshot. Do not claim a child reviewed edits it never received.

Retain `taskId`; use `task_status` and `task_cancel` for that task. Bound waits and avoid
duplicating active work. `childThreadId` is backing storage, not a new review target.
For a new review round, call `delegate_task` again with the original brief, prior
findings, responses, and unresolved objections, and a distinct stable `clientRequestId`.

`create_threads` and `t3_thread_launch` create top-level conversations. Use them only
when the user asks for separate conversations, not as a substitute for a subagent.
For an authorized new conversation needing its own checkout, select `workspaceStrategy`
in the launch call. A `cd` or `git worktree add` inside its prompt does not bind T3's
workspace. Retain the returned thread ID and inspect an ambiguous launch before retrying.

## PRs and ongoing work

If available, call `link_pull_request` immediately when creating or starting work on a
PR. Link every layer of a stack. Before finishing, call `list_thread_pull_requests` and
link missing PRs from this work. Report linking failures. A delegated child returns PR
URLs, head SHAs, and pending state to its parent; it does not start a watcher.

When asked to monitor a PR and `watch_pull_request` is available, call it and end the
turn. T3 wakes the task on changes; do not run a competing polling loop. When monitoring
is finished and handed back, call `unwatch_pull_request` first.

Only create schedules when the user requests recurring work. Use structured schedule
objects per the live schema and report the cadence and next run, or webhook URL.
Obtain required secrets through `request_secret` and pass its one-use reference to the
receiving tool. Never ask for secrets in chat or put them in this repository.

Use the browser the user or repository requests. This adapter does not override that
choice. T3's preview is available only when exposed and permitted for the task.
